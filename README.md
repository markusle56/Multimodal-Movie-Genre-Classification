# Multimodal movie genre classification from posters and plots

COMP 1013 Project 2.2: individual implementation (Anh Khoa Le, a1914142) of the Group 18 proposal (Project 2.1). It follows the shared design (proposal §5 and Appendix D); Appendix E allows individual implementations to differ in configuration, fusion strategy and analysis. The task is multi-label prediction of **23 genres** from a movie's **poster** (CLIP ViT-B/32) and **plot summary** (DistilBERT). It compares image-only and text-only baselines with **early and late fusion**, with macro-F1 as the primary metric. Extensions: a validation-only preprocessing and tuning study, GMU and cross-attention fusion, encoder comparisons, robustness and bias audits.

This folder holds only the experiment: running it reproduces every result in `outputs/`.

## Results (test split, 7,771 movies, mean ± s.d. over 3 seeds)

| Model | macro-F1 | micro-F1 | mAP |
|---|---|---|---|
| Image only: CLIP ViT-B/32 (multi-crop) | 0.524 ± 0.002 | 0.604 | 0.537 |
| Text only: DistilBERT (256 tokens) | 0.593 ± 0.002 | 0.656 | 0.626 |
| Late fusion: equal weights (proposal) | 0.642 ± 0.002 | 0.694 | 0.686 |
| Late fusion: per-genre weights (proposal) | 0.646 ± 0.000 | 0.696 | 0.691 |
| **Early fusion (proposal)** | **0.656 ± 0.002** | **0.701** | **0.705** |
| GMU fusion (extension) | 0.653 ± 0.001 | 0.700 | 0.700 |
| Cross-attention fusion (extension, whole-poster tokens) | 0.637 ± 0.003 | 0.687 | 0.676 |

- **Objective 1 is met.** Every fusion method beats both baselines (paired bootstrap on seed-0 predictions, p < 0.001). Early fusion beats per-genre late fusion (0.656 vs 0.646; p = 0.015) and ties with GMU (p = 0.324).
- **Validation-only design choices** (`scripts/04_tuning.py`, `outputs/results/tuning.json`):
  - The proposal's centre crop discards 37% of each poster. A multi-crop over the whole poster raises poster-only validation macro-F1 from 0.519 to 0.541.
  - A 512-token DistilBERT window changes validation macro-F1 by only +0.0027, so 256 tokens are kept.
  - The head grid's best cell (hidden 512, dropout 0.5, lr 3e-4) beats the proposal's head by +0.0087 (margin 0.0053), so it replaces it in all models.
  - Modality dropout p = 0.5 is chosen.
- **Near-duplicates** (`scripts/07_duplicates.py`): dHash ≤ 4 groups re-encoded copies and series templates. A CLIP audit of all poster pairs finds no duplicate crossing splits; the only cross-split lookalikes are franchise siblings.

## How to run

### 1. Set up the environment with uv

Install [uv](https://docs.astral.sh/uv/) if needed (`brew install uv` or `curl -LsSf https://astral.sh/uv/install.sh | sh`), then from this folder:

```bash
uv venv --python 3.13
source .venv/bin/activate
uv pip install -r requirements.txt
```

uv downloads Python 3.13 if it is not installed. Tested with Python 3.13 and PyTorch on an Apple M3 (16 GB, MPS); CUDA and CPU are detected automatically. `requirements.txt` caps each package below its next major version and notes the exact version tested.

### 2. Download the dataset

The dataset (about 3 GB) is not in the repository, so a fresh clone has no `data/` folder. The download needs a Kaggle API token at `~/.kaggle/kaggle.json` (Kaggle → Settings → Create New Token).

```bash
kaggle datasets download -d javierurea/simplified-mm-imdb -p data --unzip
```

This gives `data/data.npy` and `data/images.npz`. To keep the dataset elsewhere, set `MMIMDB_DATA=/path/to/folder` instead, or make `data` a symlink to it (git ignores either).

### 3. Run the pipeline

```bash
bash run_pipeline.sh
```

With the environment activated, the script uses `python` on `PATH`; without activating, run `PY=.venv/bin/python bash run_pipeline.sh`. It runs these steps in order:

| Step | Script | Output |
|---|---|---|
| Duplicates, label conflicts, 60/10/30 grouped split, 5 text variants | `01_preprocess.py` | `outputs/splits/` |
| Frozen encoder features (CLIP, DistilBERT, BERT, ResNet, ViT) | `02_featurise.py` | `outputs/features/` |
| Text cleaning and pooling chosen on validation | `03_ablation.py` | `ablation.json`, `choices.json` |
| Poster encoding, context length, head grid, modality dropout, cross-attention | `04_tuning.py --part search` | `tuning.json` |
| 13 configurations × 3 seeds, validation-tuned thresholds | `05_train.py` | `runs.json`, `probs_*.npz` |
| Thresholds and late-fusion weights (seed 0) | `04_tuning.py --part decision` | `tuning.json` |
| Significance, overfitting, missing modality, bias, failures | `06_analyse.py` | `analysis.json` |
| Near-duplicate audit and leakage simulation | `07_duplicates.py` | `duplicates.json`, `outputs/figures/` |
| Exploratory data analysis, executed in place | `notebooks/EDA.ipynb` | notebook outputs |

Results files are in `outputs/results/` unless noted.

**What is in the repository.** Everything in `outputs/` is generated by the pipeline. The large files are excluded and must be regenerated with `run_pipeline.sh`: cached features (`outputs/features/`, ~8.6 GB), trained heads (`outputs/models/`, ~106 MB) and the cleaned texts. The small results (`outputs/results/`, `outputs/splits/meta.csv` and `choices.json`, `outputs/figures/`, about 50 MB) are kept so the numbers can be checked without re-running.

- End-to-end runtime is about 3 hours: feature extraction about 1 hour, the tuning study about 30 minutes, and training all models with 3 seeds about 90 minutes, mostly cross-attention on 147 whole-poster tokens per movie.
- Disk: cached features take about 8.6 GB (the cross-attention patch tokens are memory-mapped, about 5.9 GB). Posters are memory-mapped from the uncompressed `.npz`; features are stored as float16.
- Single steps can be re-run once their inputs exist, for example `python scripts/05_train.py --only early_fusion gmu --verbose`.

### Reproducibility

- The split uses seed 42 and every neural model runs with seeds 0, 1, 2. All preprocessing choices are recorded in `outputs/splits/choices.json`.
- **Shared split:** by default the 60/10/30 duplicate-aware split is regenerated (15,567 / 2,605 / 7,771; 11 label-conflict movies and 5 exact copies excluded; the proposal's Table B.1 has 15,581 / 2,595 / 7,783). To use the group's exact split, place it at `data/shared_split.csv` (columns `idx,split` with values train/val/test) and re-run the pipeline.

## Data and licence
Simplified MM-IMDb (Ureña, 2024; Kaggle) is derived from MM-IMDb (Arevalo et al., 2017). It holds 25,959 movies, each with a 256×160 poster, a plot summary and 23 binary genre labels. The data is movie-level content with no personal records. Posters and plots remain copyrighted, and use follows the dataset's licence and source terms.
